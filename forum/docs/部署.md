# 方块盒子论坛 · 部署上线

本地能跑（`node server/index.js`）之后，上线只差三件事：**一台服务器**、**一个子域名**、**一层 HTTPS**。
论坛是独立服务，官网继续留在 GitHub Pages，两边互不影响。

## 0. 需要准备什么

| 项目 | 说明 |
| --- | --- |
| 服务器 | 1 核 1 核 512 MB 内存就够起步（SQLite 很省），系统推荐 Debian 12 / Ubuntu 22.04 |
| Node.js | **≥ 22.5**（要用内置的 `node:sqlite`）。`node -v` 看一下，低于 22.5 先升级 |
| 域名 | 加一条解析：`forum.blockbox.cc.cd` → 服务器 IP（A 记录）。原来的官网域名不用动 |
| 端口 | 如果是国内服务器，80/443 通常要备案；不想备案就换香港/海外机，或者先用 `http://IP:3210` 试 |

上线后论坛地址就是 `https://forum.blockbox.cc.cd`，官网导航里加个「论坛」外链即可。

### 可选依赖：sharp（只影响图片压缩）

论坛零依赖就能跑，内置的 PNG 处理不需要装东西。想让 **JPEG / WebP / GIF** 也自动压缩、
出缩略图、按 EXIF 摆正方向，在部署目录里装一次即可：

```bash
npm install sharp      # 会拉预编译二进制，装完重启服务
```

装好后上传接口返回的 `engine` 会变成 `sharp`；Docker 部署时在 `Dockerfile` 里加一行
`RUN npm install --omit=dev sharp` 再重新 build 即可。

## 1. 方式 A：直接用 systemd（推荐，最轻）

```bash
# 1) 传代码（在本地执行；data/ 不用传，服务器上会自动建）
scp -r 方块盒子论坛 root@你的服务器:/opt/blockbox-forum

# 2) 服务器上
cd /opt/blockbox-forum
cp .env.example .env
```

改 `.env`，至少要改这几行：

```ini
HOST=127.0.0.1          # 只让本机访问，由 Nginx/Caddy 对外
PORT=3210
PUBLIC_ORIGIN=https://forum.blockbox.cc.cd
TRUST_PROXY=1           # 在反向代理后面，取真实 IP
SECURE_COOKIE=1         # 已经上了 HTTPS
SITE_NAME=方块盒子论坛
```

装成系统服务：

```bash
sudo cp deploy/blockbox-forum.service /etc/systemd/system/
# 按实际情况改 User / WorkingDirectory，然后把目录交给该用户
sudo chown -R www-data:www-data /opt/blockbox-forum
sudo systemctl daemon-reload
sudo systemctl enable --now blockbox-forum
systemctl status blockbox-forum        # 看到 active (running) 就成了
journalctl -u blockbox-forum -f        # 看日志
```

### 让管理后台能发布首页公告

管理后台的「首页公告」会把公告写进官网根目录的 `announcement.json`（启动器首页读的就是它）。
论坛服务默认只能写自己的 `data/`，所以要在服务器上多做一步：允许论坛服务写这个目录
（systemd 的 `ProtectSystem=strict` 会挡住）。仓库里的 GitHub Actions 部署会自动做这一步；
手动部署时执行：

```bash
sudo mkdir -p /etc/systemd/system/blockbox-forum.service.d
sudo cp deploy/blockbox-forum-announcement.conf /etc/systemd/system/blockbox-forum.service.d/
sudo systemctl daemon-reload && sudo systemctl restart blockbox-forum
```

部署脚本在同步官网文件后会自动把公告文件交给论坛服务用户（`www-data`）；如果是手动部署，
自己补一条：

```bash
sudo chown www-data:www-data /var/www/blockbox/announcement.json
```

路径默认就是 `/var/www/blockbox/announcement.json`，一般不用改；官网目录不在这个位置时，
在 `.env` 里指定：

```ini
ANNOUNCEMENT_FILE=/var/www/blockbox/announcement.json
```

发布后管理后台会显示「公告文件可写」；显示不可写就按上面的路径和权限检查。
启动器首页公告栏最长约 10 分钟刷新一次。以后以论坛数据库里的公告为准，每次部署重启都会
把最新公告重新写回这个文件（官网仓库里的那份用于首次初始化）。同一个文件也带管理后台
「启动重要公告」写进去的 `important` 字段，启动器启动时据此弹窗，部署方式与首页公告完全一样。
Docker 部署时记得把官网目录挂进容器，并交给容器用户写。

## 2. 方式 B：Docker

```bash
cd /opt/blockbox-forum
mkdir -p data && sudo chown -R 1000:1000 data    # 容器内以 uid 1000 运行
docker compose up -d --build
docker compose logs -f
```

- 数据在 `./data`（数据库 + 上传的图片），删容器不会丢
- 容器只监听 `127.0.0.1:3210`，外面照样由 Nginx/Caddy 转发
- 升级：`git pull`（或覆盖文件）后 `docker compose up -d --build`

## 3. 配 HTTPS 反向代理
### Caddy（最省事，自动申请证书）

```bash
sudo apt install caddy
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
# 把文件里的域名改成你的，然后
sudo systemctl reload caddy
```

### Nginx

```bash
sudo cp deploy/nginx-forum.conf /etc/nginx/conf.d/forum.conf
sudo certbot --nginx -d forum.blockbox.cc.cd    # 没有证书时先签
sudo nginx -t && sudo systemctl reload nginx
```

> `client_max_body_size` 要和 `.env` 里的 `MAX_IMAGE_BYTES` 对得上，否则传图会 413；
> 开了插件帖要再考虑 `MAX_PLUGIN_BYTES`（默认 20 MB），取两者较大值，否则传插件包会 413。

## 4. 发信邮箱：外部 SMTP 或自托管 Postfix

启动器里的「验证邮箱」功能需要服务器能发邮件。出口由 `.env` 的 `SMTP_*` 决定，
SMTP_HOST 留空表示不发邮件，相关接口会返回「邮件服务尚未配置」。

### 4.1 方式一：外部邮箱服务（最省事）

用 QQ / 163 邮箱的授权码或邮件推送服务（阿里云邮件推送等），`.env` 配置见
`.env.example` 里的注释。适合不想自己维护邮件服务的场景。

### 4.2 方式二：自托管 Postfix（发件人用自己的域名）

论坛程序连服务器本机的 Postfix（`127.0.0.1:25`，无认证）投递，发件人可以是
`noreply@mcblockbox.top` 这样的自有域名地址，不依赖任何第三方邮箱。

**先确认一个前提**：阿里云 / 腾讯云等国内云默认**封 25 端口出站**（防止滥发垃圾邮件），
先在控制台申请解封；解封不下来就只能走方式一，或给 Postfix 配 `relayhost` 借道转发。

**安装（Ubuntu / Debian）**：

```bash
sudo apt install postfix
# 类型选「Internet Site」，System mail name 填你的域名，如 mcblockbox.top
```

**`/etc/postfix/main.cf` 关键项**（其余保持默认）：

```ini
myhostname = mcblockbox.top        # 和你 IP 的反向解析（PTR）对齐
myorigin = mcblockbox.top          # 本地发信的默认域名
mydestination = localhost          # 千万别包含你的域名，否则本域邮件会被错误投递到本机
inet_interfaces = loopback-only    # 只监听本机回环：论坛程序连 127.0.0.1，不对外暴露
inet_protocols = ipv4
```

可选：开启 STARTTLS（回环提交非必需；论坛客户端连本机 Postfix 会自动信任自签名证书）：

```ini
smtpd_tls_cert_file = /etc/ssl/certs/ssl-cert-snakeoil.pem
smtpd_tls_key_file = /etc/ssl/private/ssl-cert-snakeoil.key
smtpd_tls_security_level = may
```

**重启并自测**：

```bash
sudo systemctl restart postfix
echo "正文" | sendmail -f noreply@mcblockbox.top 你的邮箱@example.com
tail -f /var/log/mail.log          # 看到 status=sent 才算真的发出去了
```

**论坛 `.env`**：

```ini
SMTP_HOST=127.0.0.1
SMTP_PORT=25
SMTP_SECURE=0
SMTP_USER=
SMTP_PASS=
MAIL_FROM=noreply@mcblockbox.top
```

**让邮件别进垃圾箱**（自托管的关键，缺一样都容易被拒收）：

1. **PTR 反向解析**（最重要）：在 VPS 控制台把服务器 IP 的 rDNS 设为 `mcblockbox.top`，
   必须和 `myhostname` 一致，QQ 邮箱、Gmail 都会查
2. **SPF**：域名加 TXT 记录 `@  →  "v=spf1 ip4:服务器IP -all"`
3. **DMARC**：`_dmarc  →  "v=DMARC1; p=none; rua=mailto:postmaster@mcblockbox.top"`
4. **DKIM**（强烈建议）：装 `opendkim` 生成密钥对，DNS 加 `selector._domainkey` TXT 记录，
   Postfix 挂上 milter 对每封信签名，具体参照 opendkim 的文档

改完 `.env` 重启论坛服务后，在启动器里给测试邮箱发一封验证码实测一下。

## 5. 上线检查清单

- [ ] `PUBLIC_ORIGIN` 填的是真实域名（不是 `127.0.0.1`）
- [ ] HTTPS 打开后把 `SECURE_COOKIE=1`（否则浏览器会拒收 Cookie，表现为"登录后立刻掉登录"）
- [ ] 反代后面把 `TRUST_PROXY=1`（否则限流按代理 IP 算，全站共用一个桶）
- [ ] 第一个账号注册成管理员后，**立刻改掉默认密码**（或先用 `node scripts/set-admin.js 管理员 新密码`）
- [ ] 想关闭注册就设 `REGISTER_OPEN=0`
- [ ] 防火墙只开 22 / 80 / 443，不要直接暴露 3210
- [ ] 要启用邮箱验证就把 `SMTP_*` 配好（见上一节），并用真实邮箱实测一封
- [ ] 配了 CDN 的话，打开页面确认样式和图片地址已经是 CDN 域名（见第 9 节）
- [ ] 配好每日备份（见下一节）

## 6. 备份与恢复

```bash
npm run backup                  # 备份到 data/backups/forum-<时间>.db（自动保留最近 10 份）
node scripts/backup.js /mnt/backup   # 也可以指定目录
```

备份用的是 SQLite 的 `VACUUM INTO`，**不用停服**，WAL 里没落盘的数据也会带上；同时会把
`data/uploads/`（头像和帖子里的图片）复制一份。

加一条定时任务：

```cron
# 每天凌晨 3:20 备份
20 3 * * * cd /opt/blockbox-forum && /usr/bin/npm run backup >> /var/log/blockbox-forum-backup.log 2>&1
```

**恢复**：停服务 → 用备份文件覆盖 `data/forum.db` → 删掉 `forum.db-wal` / `forum.db-shm` → 启服务。

## 7. 升级与迁移

- **升级**：覆盖新代码 → `systemctl restart blockbox-forum`。启动时会自动补齐缺失的表（`CREATE TABLE IF NOT EXISTS`），
  现有数据不会动。改过的新字段如果涉及旧表结构，会单独在更新日志里说明。
- **迁移服务器**：停服 → 把整个 `data/` 目录连同代码一起拷走 → 新机器上起服务即可。
- **换端口**：改 `.env` 的 `PORT`，同步改反向代理里的上游端口。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `端口 3210 已被占用` | 已经开着一个了（`ss -ltnp \| grep 3210` 找进程），或改 `PORT` |
| 登录成功但刷新就掉登录 | `SECURE_COOKIE=1` 但实际是 `http://` 访问，改回 0 或补上 HTTPS |
| 上传图片提示 413 | Nginx 的 `client_max_body_size` 小于图片大小 |
| 限流把所有人当成一个人 | 反代后面没开 `TRUST_PROXY=1` |
| 时间显示不对 | 内容时间用 Unix 秒，显示按浏览器本地时区，一般不用管；日志时间受服务器时区影响 |
| 页面能开但样式是旧的 | 改过 CSS/JS 后要提升 HTML 里的 `?v=` 版本号，浏览器才会重新拉 |
| 样式或图片从别人的 CDN 域名加载不出来 | CDN 的源站要指到论坛服务器、回源 Host 填论坛自己的域名，并且缓存键要带上查询参数 |
| 换过 CDN 域名，老帖子里的图片怎么办 | 不用管：正文里存的是 `/uploads/…` 站内相对路径，改了 `CDN_BASE` 重启就整体换过去 |
| 搜索搜不到新帖 | 新帖会实时写入搜索索引；如果直接改过数据库，管理员调 `POST /api/admin/rescan` 重算计数 |

## 9. 公开资源走 CDN

页面脚本样式（`/assets/`）和帖子 / 头像图片（`/uploads/`）是论坛里量最大的两类请求，
它们本来就是公开、可长期缓存的，最适合交给 CDN。接口、页面和登录态仍然走论坛自己的域名，
人机验证、Cookie 这些都不受影响。**插件帖的 `.BlockBox` 包也落在 `/uploads/` 下**，
配了 CDN 后插件下载地址自动就是 CDN 域名，不用额外配置。

1. 在 CDN 控制台加一个加速域名（比如 `cdn.blockbox.cc.cd`），源站指向论坛服务器；
   回源 Host 填论坛自己的域名（`forum.blockbox.cc.cd`），回源协议跟论坛保持一致；
2. 缓存规则只对 `/assets/`、`/uploads/` 开缓存，缓存时间跟随源站的 `Cache-Control`
   （论坛已经给这两类路径发了 `public, max-age=2592000, immutable`）；
   **缓存键一定要带上查询参数**，`forum.css?v=20261110a` 这种版本号是靠它区分的；
3. 论坛 `.env` 加一行，然后重启服务：

```ini
CDN_BASE=https://cdn.blockbox.cc.cd
```

重启后打开任意页面，`<link>`、`<script>` 和图片地址都会变成 CDN 域名；启动日志里也会打印
`公开资源走 CDN：https://cdn.blockbox.cc.cd`。

### 本站现在用的 CDN（yuncname 面板）

本站买的是一个按流量计费的 `yuncname` 回源 CDN，面板是「CDN控制面板」（kangle），
访问时响应头会带 `x-cache: HIT from kangle server hk1 cdn`。完整流程：

1. **DNS**：`cdn` 这条记录做成 `CNAME` → `s4012656.w.yuncname.com`（香港节点），
   代理 / CDN 开关保持**关闭**（灰色、仅 DNS），否则会变成两层 CDN 互相打架；
2. **面板 · 域名绑定**：域名 `cdn.mcblockbox.top`、源站IP `202.181.26.190`、回源协议 `http`；
3. **面板 · SSL证书设置**：它只支持手工上传，把服务器上的

   ```bash
   /etc/letsencrypt/live/cdn.mcblockbox.top/fullchain.pem   # ssl证书内容（四段，别漏）
   /etc/letsencrypt/live/cdn.mcblockbox.top/privkey.pem     # ssl证书密钥内容
   ```

   整段贴进两个框里提交。**证书 90 天到期，续期后要重新贴一次**（下面有到期提醒办法）；
4. **面板 · 缓存设置**：功能开关打开，加一条规则——类型 `文件扩展名`、
   值 `css,js,svg,ico,png,jpg,jpeg,gif,webp,woff2`、缓存时间 `2592000` 秒，`强制缓存` 不勾
   （源站已经发了 `immutable`，跟随源站最稳）；
5. **服务器**：跑一次就完事，之后改 CDN 域名也用它：

   ```bash
   bash /opt/blockbox-forum/deploy/开启CDN.sh
   ```

最后验证：

```bash
curl -sI https://cdn.mcblockbox.top/assets/forum.css | grep -i 'x-cache\|cache-control'
```

第一次 `MISS`，第二次起 `HIT` 就说明缓存生效了。页面和 `/api/` 不在缓存规则里，
始终回源，所以登录、发帖、人机验证都不受影响。

几点要知道：

- **只填协议 + 域名**，带路径（如 `https://cdn.xxx.com/forum`）会被忽略，启动日志里会提醒；
- 不填 `CDN_BASE` 就完全保持原样，资源由论坛自己发；如果 CDN 用的是"整站加速"模式，
  也可以不配，让 CDN 按路径规则缓存 `/assets/`、`/uploads/`（页面和接口不缓存）；
- 接口返回的仍然是 `/uploads/…` 站内相对路径，帖子正文里存的也是相对路径，
  所以换 CDN 域名、以后把图片挪去对象存储，都不用改老数据；
- 改过 CSS/JS 记得提升 HTML 里的 `?v=` 版本号，CDN 和浏览器都靠它拿新文件；
- 删掉图片（图库删除、删帖）后，CDN 上可能还留着最多 30 天的缓存，介意就在控制台刷新那条 URL；
- 源站的 `/assets/`、`/uploads/` 已经放开了 `Access-Control-Allow-Origin: *`，
  CDN 回源或别的页面直接引用都不会被跨域拦住。

### 官网安装包下载限速

官网一键下载和启动器应用内更新都从 `/releases/files/…` 拿安装包，默认每个下载请求
限速 **400KB/s**（100MB 的包大约 4 分钟下完），用来压住服务器出口带宽和月流量。
改 `.env` 的 `DOWNLOAD_RATE_LIMIT_KB` 即可调整，填 `0` 关闭限速，改完重启论坛服务生效：

```bash
DOWNLOAD_RATE_LIMIT_KB=400
```

限速在论坛进程里按每个连接算，所以只有真正由源站发出去的下载才受限：

- 现有 CDN 缓存规则只匹配 `css,js,svg,ico,png,jpg,jpeg,gif,webp,woff2`，安装包默认回源，限速正常生效；
- 如果以后在 CDN 面板给 `/releases/` 也开了缓存，命中缓存的下载不经过源站，就绕过了这个限速——
  要么别给安装包开缓存，要么在 CDN 面板单独设带宽上限。
